오늘 고민한 내용 정리 (02. Nov. 2026)
프로젝트의 목적과 환경
- 2번째 프로젝트는 AWS나 Kubernetes를 설치하는 것 자체가 목적이 아니라, 주가 데이터를 수집·저장하고 조건에 따라 알림을 보내는 서비스를 운영하는 프로젝트예요.
- 주식이 첫 MVP이고, News는 나중 단계로 두기로 했어요.
- 개발은 로컬 kind, 운영은 AWS EC2의 k3s로 구상했어요. Terraform은 AWS 인프라와 운영 환경의 Argo CD 설치에 쓰고, Discord는 AWS 외부 서비스로 둡니다.
- Python 수집 로직은 애플리케이션 영역에 가깝지만, 작은 수집기를 컨테이너화하고 스케줄링·배포·관측·장애 대응하는 과정에서 DevOps 경험을 보여주려는 방향이에요.
Argo CD와 파일 역할
- root-app.yaml은 kubectl apply로 root Application을 처음 만드는 파일이에요.
- root Application은 kubernetes/argocd 경로를 바라보고, 그곳의 kustomization.yaml이 자식 Application 목록을 구성합니다.
- Argo CD는 Git 변경을 확인하고 Kustomize를 다시 실행해 원하는 리소스를 계산한 뒤, 클러스터 상태와 맞춥니다. 같은 폴더에 있는 모든 YAML이 자동 배포되는 건 아니고 Kustomize 목록에 포함된 리소스가 대상이에요.
- Grafana·Prometheus·PostgreSQL은 Application이 각 차트 경로를 가리키고, Helm 차트가 만든 Kubernetes 리소스를 Argo CD가 배포하는 구조예요. Argo CD Application 자체는 Service가 아닙니다.
DB와 모니터링 범위
- DB 초기화는 schema.sql 대신 PostgreSQL README에 적힌 init.sql 방식으로 하기로 했고, 마이그레이션 도구는 지금 당장 범위에서 미루기로 했어요. 제가 앞서 README에 적힌 결정을 놓치고 schema.sql 연결이 빠졌다고 반복해서 지적한 건 제 실수였습니다.
- CronJob은 실행 후 종료되므로 자체 /metrics를 Prometheus가 안정적으로 긁기 어렵다는 점을 이야기했어요. 하지만 현재는 PostgreSQL 흐름에 집중하고, Prometheus는 뒤 단계로 두기로 했습니다.
Collector 차트와 현재 상태
제가 다시 읽은 파일 기준으로는:
- root Kustomize 목록에 PostgreSQL·Grafana·Prometheus·Stock·News Application이 포함돼 있어요.
- Stock과 News Application은 각자 폴더를 가리키고, 둘 다 collector Namespace를 대상으로 하며 CreateNamespace도 올바르게 적혀 있습니다.
- Stock 차트의 잘못된 dependencies는 제거됐고, type: application은 주석 처리돼 있어요. type은 생략해도 기본값이 application입니다.
- News 차트에도 type이 없지만 문제가 아닙니다. 두 차트 모두 아직 실제 템플릿과 workload가 없다는 점은 알고 있다고 하셨어요.
- 현재 Stock에 values.yaml은 없어요. 필수 파일은 아니지만 이미지 설정, 실행 주기, 리소스 값 등을 템플릿에 하드코딩하지 않으려면 나중에 추가할 수 있습니다.
- appVersion 값은 차트의 애플리케이션 버전을 나타내는 정보이고, 그 자체로 컨테이너 이미지 태그를 자동 지정하지는 않아요. 실제 연결하려면 Helm 템플릿에서 그 값을 참조해야 합니다.
오늘의 다음 작업 후보
Stock 쪽은 이제 차트가 무엇을 가져오는지보다, 이 차트가 어떤 Kubernetes workload를 정의할지가 다음 학습 지점이에요. values.yaml로 설정을 분리하고 templates/에 CronJob을 정의한 뒤, 이미지와 함께 로컬 kind에서 실행하는 순서가 자연스럽습니다. News 차트도 같은 방식이지만 MVP 이후로 미룰 수 있어요.

그리고 오늘은 파일을 읽기만 했고, 제가 수정하거나 배포한 내용은 없습니다. root-app 파일은 확인 과정 중 작업 폴더에서 잠시 보이지 않았지만 Git 최신 커밋에는 있었고, 이후 다시 확인했을 때 작업 폴더에도 존재했습니다. 제가 삭제한 건 아니며, 사라진 원인까지는 확인하지 못했습니다.
