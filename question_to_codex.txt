I'm running K3S on a single EC2 instance in AWS.

Current architecture:

- Terraform creates:
  - EC2
  - EBS Volume
  - Volume Attachment
- Ansible installs:
  - K3S
  - Helm
  - ArgoCD
- ArgoCD deploys PostgreSQL (Bitnami Chart)

PostgreSQL values:

primary:
  persistence:
    enabled: true
    size: 2Gi
    storageClass: postgres-storage

Current StorageClass:

apiVersion: storage.k8s.io/v1
kind: StorageClass
metadata:
  name: postgres-storage
provisioner: rancher.io/local-path

Problem:

local-path dynamically creates PVs on the node filesystem, but I want PostgreSQL data to be stored on the EBS volume created by Terraform.

I want to keep EBS lifecycle managed by Terraform (encrypted, prevent_destroy, etc.), not dynamically create EBS volumes from Kubernetes.

What is the recommended production-grade approach to connect a Terraform-managed EBS volume to a Bitnami PostgreSQL Helm deployment on K3S?

Specifically:
- Should I use CSI driver with a pre-provisioned EBS volume?
- Should I create a PersistentVolume manually and bind it to the PVC created by the PostgreSQL chart?
- How should filesystem creation and mounting be handled?
- Is using local-path with a custom mount point considered a bad practice for this scenario?
